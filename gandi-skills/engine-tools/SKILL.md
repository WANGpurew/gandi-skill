# 引擎搭建：物理/光照/粒子/瓦片地图

## R — 原文 (Reading)

> "引擎扩展的配置挂在文件夹上，不挂在角色也不挂在单个造型上。造型列表里的文件夹就是分组……各级是相加的：最外层（不在任何文件夹里）配的 + 每一级文件夹配的 + 这张造型自己加的，一起生效，从外往里。"

> — Gandi 3.0 功能文档·引擎·物体 / slug: engine（行14254/14257；源：candidates/framework.md f36、case.md c11）

> "一个角色怎么动（不动的地面、会掉下去的箱子、玩家操作的主角）在装配编辑器里选，按下绿旗就生效，不需要写积木；积木用来处理运行起来以后的事：推一下、问碰到了谁、连关节、灌一池水。"

> — Gandi 3.0 功能文档·物理·运动类型 / slug: physics（行14798-14799；源：candidates/framework.md f37）

> "刚装上时环境光是 100% 的白色，没有灯的地方和原来完全一样，灯照在上面也看不出来。加了第一盏灯之后，画面上方会提醒「环境光强度已满，光源效果不可见」，点「降低环境光」把环境光强度降到 35%，或者在场景那一层换一种风格。"

> — Gandi 3.0 功能文档·光照·刚装上 / slug: lighting（行15980-15981；源：candidates/counter-example.md ce13）

## I — 方法论骨架 (Interpretation)

把物理/光照/粒子/地图四类进阶玩法，统一成"编辑态配置 + 运行态积木"两层来搭：
① **共用装配编辑器**——四者的配置都挂在造型文件夹上，可叠加项（碰撞体/灯/发射器）按"最外层 + 各级文件夹 + 本张造型"从外到里相加；
② **一份参数唯一归属**——物理身体、受光挡光这类"一份"参数不能叠，必须把某文件夹"设为物体"定唯一主人，内部只逐层覆盖改过的项，没改的跟上一级；没归入任何物体的用"默认"物体；
③ **角色/世界分工**——运动类型（关/静止/动态/随脚本/角色）与碰撞体在编辑器里配好、绿旗即生效；角色手感有平台跳跃/俯视/格子三模式与四套现成手感，物理世界设视角（横版重力 y=-980 / 俯视摩擦 8）、时间倍率、边界；
④ **光照**——灯配在造型某层或摆场景、8 种风格，加灯后先把环境光从 100% 降到约 35% 才看得见；需 WebGL2；
⑤ **粒子三件套**——效果（作品级、1-16 层、四节参数）、发射器（5 种时机含"消失时"做死亡爆炸）、播放积木（"在[我]播放[效果]"放完自消）；
⑥ **地图**——长在地图角色上，四种格子（方格/等距/交错/六边形，后两者无地形），瓦片设碰撞（不挡/实心/平台）、标签、属性、寻路代价，58 块积木读改写与找路；需 WebGL2。
核心洞察：编辑态把"怎么配置"一次配好，积木只负责运行起来以后的交互；且四类积木的改动都只作用于本次运行、停止即还原，不写作品。

## A1 — 书中的应用 (Past Application)

### 案例一：物理平台跳跃搭建（worked_example，slug: physics / c12）
- **问题**：做横版平台跳跃游戏，要能跑、能跳、离边还能起跳、贴墙不掉下去，且起步刹车有加速度。
- **方法执行**：扩展库加"物理"→装配编辑器把角色类型选"角色"、模式用"自动"（横版自动按平台跳跃）→ 四套手感选一套再微调最高速度/跳跃高度/离边宽限/预按/蹬墙/爬梯 → 碰撞盒底边画到造型脚底 → 把"按平台角色走：左右[ ] 跳<>"放进"重复执行"每帧跑一次，左右填 -1 到 1、跳填跳键按着没有。
- **结论**：文档所述效果——起步刹车有加速度、空中可转向；离边宽限内仍能起跳、按住跳满高度点按跳得低，能走台阶/上下坡/站移动平台/蹬墙跳/单向平台跳下。

### 案例二：粒子"消失时"做死亡爆炸（scenario，slug: particles / c13）
- **问题**：敌人被打死（隐藏/删除）时想在最后位置炸一下，又不想为此写积木。
- **方法执行**：装配编辑器"粒子效果"页给角色挂发射器、效果选爆炸类→"发射时机"选五种里的"消失时"（另四种：持续/移动时/出现时/由积木触发）→ 角色隐藏、被删除或换走造型时自动在最后位置放一遍。
- **结论**：文档所述效果——"死的时候炸一下"用这个时机即可、不用写积木；"放一遍"指会自己结束的效果完整放完，一直发的效果只放开头那一下爆发。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 要做带重力的平台跳跃、俯视角或格子移动游戏，想用现成物理手感而不是从零写移动。
2. 想给作品加 2D 光照、夜景/室内氛围，或做火焰雨雪爆炸魔法等粒子效果。
3. 要用瓦片地图铺关卡、设平台/实心碰撞、做自动寻路或迷雾。
4. 配好了灯/碰撞体却不生效、或积木改了运行效果想问"为什么停手就没了"。

### 语言信号
- "怎么做重力/平台跳跃/角色手感 / 碰撞体 / 关节 / 液体软体"
- "怎么加光照 / 灯 / 夜景 / 环境光 / 画面风格"
- "怎么制作粒子爆炸 / 火焰 / 死亡特效 / 发射器"
- "瓦片地图 / 寻路 / 格子地图 / 地形 / 六边形网格 / 迷雾"

### 与相邻 skill 的区分
- 与 `blocks-authoring`（also_read）：本卡管"编辑态装配配置 + 引擎专属积木"；blocks 卡管普通积木移动、自制/全局积木、作用域。普通匀速移动用 blocks，别上物理引擎。
- 与 `run-debug`（also_read）：本卡管引擎搭建与硬约束；run-debug 管卡顿排查与断点。"物理/粒子卡顿时先确认 WebGL2 与上限"是两卡衔接点，性能定位交 run-debug。
- 与 `scenes-assets`（also_read）：引擎配置挂造型文件夹、跨场景复用由 scenes 的资源库规则管，本卡不重复素材复用决策。

## E — 可执行步骤 (Execution)

**输入契约**：一个要加物理/光照/粒子/地图玩法的 Gandi 作品 + 玩法意图（如"平台跳跃+死亡爆炸"）+ 已确认浏览器支持 WebGL2。
1. **加扩展与确认 WebGL2**：扩展库装"物理/光照/粒子/地图"，或装配页"+物理/+粒子"等；确认 WebGL2 可用。完成标准：相应装配页/编辑器能打开；判停：无 WebGL2 则光照与地图不可用。
2. **装配配置（层级相加 + 唯一归属）**：把碰撞体/灯/发射器挂在造型文件夹层级，按"最外层+各级文件夹+本张造型"从外到里相加；"一份"参数把文件夹"设为物体"定唯一归属，单张造型只覆盖改过的项。完成标准：几十帧造型共用一套配置、换装各配各的；克隆体读本体。
3. **搭物理（按需）**：选类型（关/静止/动态/随脚本/角色）与手感（平台跳跃/俯视/格子、四套手感）→ 画碰撞体（没画按轮廓算）→ 舞台设物理世界（横版重力 y=-980/俯视摩擦 8、时间倍率、边界）→ 用积木处理运行时交互（积木只说"我"）。完成标准：绿旗即按设定运动、积木只改本次运行。
4. **搭光照（按需）**：灯配造型层或摆场景 → 选 8 种风格/环境光/日月光 → 加第一盏灯后按"降低环境光"到约 35%。完成标准：加灯后画面有明暗差别；判停：环境光仍 100% 则灯不可见。
5. **搭粒子（按需）**：粒子编辑器做效果（1-16 层、发射/运动/外观/子粒子四节）→ 挂发射器选时机（含"消失时"做死亡爆炸）→ 积木"在[我]播放[效果]"。完成标准：播放一次能自行结束。
6. **搭地图（按需）**：地图角色上开地图编辑器 → 画笔/矩形/油漆桶画地形（自动拼边角）→ 设瓦片碰撞/标签/属性/寻路代价 → 规则层自动铺、标记摆角色 → 58 积木沿地图移动/碰瓦片/找路/存档。完成标准：角色能沿最短路绕开实心走；判停：名字填错会静默 no-op，须核对是否真生效。
7. **核对上限**：物体 1024/关节 4096/节点 1 万、粒子 1 万、粒子代码 32768 字符、地图填成 ≤400 万格。完成标准：各项在容量内。
**输出契约**：一份装配好引擎配置的作品（配置层级表 + 物理/光照/粒子/地图参数 + 运行交互积木）+ WebGL2 与上限核对记录 + "停止后积木改动还原"的验证说明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 普通匀速/简单移动（如菜单滑动）——用 `blocks-authoring` 直接改坐标，不必上物理引擎。
- 引擎运行卡顿、想找慢帧/慢积木——用 `run-debug`；素材本身画得对不对——用造型/声音创作能力。
- 场景间切换与素材复用的架构决策——用 `scenes-assets`。

### 作者在文档中警告的失败模式
- 积木改动不写作品：物理/光照/粒子/地图积木的改动只作用于本次运行、停止即还原，不能指望它把"跑完的状态"存成作品初始值。
- 环境光 100% 坑：刚装光照时环境光是 100% 白，灯打上去看不出；必须降到约 35% 或换风格才可见，否则误以为功能坏了。
- 地图填错不报错：图层名/瓦片名/标记种类找不到时积木什么都不做（no-op），没地图时报告空、判断不成立——全程不报错，须靠核对或问题面板发现。
- 一份参数不能叠：物理身体、受光挡光必须唯一归属，没"设为物体"就多处分歧；没归入物体的造型走"默认"物体。

### 文档的盲点 / 局限
- 硬约束：光照与地图需 WebGL2；上限物体 1024/关节 4096/节点 1 万、粒子 1 万、粒子代码 32768 字符、地图填成 ≤400 万格；粒子接物理仅舞台生效。
- 地图四种格子中交错/六边形没有地形功能；地图协作为只读，需"编辑角色"权限，且运行改动不同步。
- 旧版物理积木多已失效需替换；粒子发射器合计 ≤256（满则最早退场）、单效果 ≤16 参数/16 层。

### 容易混淆的邻近方法论
- "编辑态配置"（挂文件夹、设为物体、绿旗即生效）与"运行态积木"（只改本次、说"我"、停止还原）是两套动作，别把配置写成积木或反之。
- 粒子"效果"（作品级、改一次处处变）、"发射器"（挂角色/摆场景）、"播放"（放完自消）是三件不同的事。
- 物理"角色"类型（主角/敌人，不受力不被推、引擎算步）与"动态"类型（受力会掉会弹）手感完全不同。
