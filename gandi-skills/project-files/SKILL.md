# 作品文件、版本回滚与数据保全

## R — 原文 (Reading)

> "版本历史记下作品在每个时刻的样子，随时可以预览、一步还原，或者只把某个角色拿回来。改作品的时候它自己存，不用操心；改坏了、删错了、想看看昨天那一版，都从这里找。"
>
> — Gandi 3.0 功能文档·作品与文件·版本历史 / slug: version-history（源：candidates/framework.md f05）

> "删掉的角色、造型和声音不会直接消失，先进回收站。删错了可以原样捡回来。"
>
> — Gandi 3.0 功能文档·回收站 / slug: trash（源：candidates/framework.md f07）

> "本机版本只在这台电脑的这个浏览器里：换浏览器、清掉网站数据就没了，不能代替保存作品。"
>
> — Gandi 3.0 功能文档·版本历史·限制 / slug: version-history（源：candidates/counter-example.md ce01）

## I — 方法论骨架 (Interpretation)

把"改坏了、删错了、要换机"的数据安全问题，用文件+版本+回收站三层保全体系分开处理：
① **打开/保存**——文件菜单打开 .sb3（2.0 直接开），"保存到电脑"打包 .sb3（含代码文件/场景/舞台尺寸）；浏览器版须手动保存，刷新/关闭靠提示但不能代替备份；
② **版本历史兜底**——顶栏表盘/文件菜单进入，来源分本机+云端+发布；停手 30 秒自动存（最长 5 分，可改）/保存时/大改动前，内容一样或后台标签不存；
③ **回滚路径**——点条目看逐角色 diff →"预览"载旧版跑一下 →"还原到此版本"（当前先自动存成"还原前"，可二次回退）或"取回其中的角色"只拿某角色；CLI 对应 `history list/show/save/restore/delete`；
④ **回收站细粒度兜底**——误删角色/造型/声音进站（可原样还原，角色连脚本/私有变量），存本机 IndexedDB、≤60 项/200MB、不随 .sb3、清空须按两次；场景本身回不来但里面角色逐个进站，积木靠 Ctrl+Z 不进站；
⑤ **代码文件随作品走**——`.js/.py/.json/.glsl` 等建/传/改名/移动/搜索/比较，跟着作品进 .sb3（extension.js 只能一个且舞台根下）；上传 >5MB 确认、>50MB 拒收、文本须 UTF-8；
⑥ **导出发布**——顶栏"发布"导出网页/桌面/安卓，仅嵌入宿主时提供，网页版没有。
核心洞察：版本历史管"改坏回退"、回收站管"误删捡回"、.sb3 管"持久备份迁移"；前两者都在本机浏览器，清数据即丢，绝不能代替保存。

## A1 — 书中的应用 (Past Application)

### 案例一：版本回滚与找回（worked_example，slug: version-history / f05）
- **问题**：改坏了作品、删错了东西、想找回昨天那一版，但不确定该怎么安全回退。
- **方法执行**：顶栏表盘/文件菜单开版本历史 → 点条目看逐角色 diff →"预览"载旧版跑一下 → 选"还原到此版本"（系统先把当前作品存成"还原前"）或"取回其中的角色"只拿某角色 → 还原错了从"还原前"再还原。
- **结论**：文档所述效果——一步还原且留二次回退余地；预览期间不保存也不自动存；协作房间不能预览（会把旧版推给所有人），还原整个房间且需权限。

### 案例二：回收站还原误删角色（worked_example，slug: trash / f07）
- **问题**：误删了角色/造型/声音，想原样捡回来。
- **方法执行**：文件→回收站 → 找到条目 → "还原"放回作品（造型/声音回到原角色末尾）或"删除"彻底去掉 → 删场景后其内角色逐个进站、捡回落当前场景。
- **结论**：文档所述效果——进站对象可连脚本/造型/声音/私有变量原样还原；场景本身回不来（含场景变量/入口标记/顺序）；回收站存本机 IndexedDB、不随 .sb3，换机带不过去。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 刚把作品改坏或删错角色/造型/声音，想找回上一个好版本。
2. 想只取回某个角色，而不是整份覆盖当前作品。
3. 要换电脑/换浏览器迁移作品，或定期做可靠备份。
4. 要管理代码文件（上传数据、比较、改名），或导出成网页/桌面程序。

### 语言信号
- "改坏了怎么找回 / 还原上一版 / diff / 预览"
- "误删角色 / 回收站 / 只取回某个角色"
- "怎么打开/保存作品 / 备份 / 迁移到另一台电脑 / sb3"
- "代码文件怎么管理 / 上传 json / 比较文件"
- "导出网页/桌面 / 版本历史在不在文件里"
- "version history / rollback / restore / trash / backup / sb3 / export"

### 与相邻 skill 的区分
- 与 `cli-authoring`（also_read）：本卡管界面里的打开/保存、版本历史、回收站、备份迁移与数据保全；cli 卡用 `history`/`export` 等命令做工程化闭环。两者共用一套本机版本数据；CLI 找回侧重命令，本卡侧重界面流程与"版本不在文件里"的保全口径。
- 与 `scenes-assets`（also_read）：本卡管作品的"文件与版本层"，含多场景 .sb3 兼容坑；scenes 卡管"怎么设计和切换多场景"。多场景 .sb3 拿到 Scratch 保存会静默丢场景——这是两卡都要提醒的交界点，本卡强调备份后果，scenes 强调设计时使用旧编辑器会丢失。

## E — 可执行步骤 (Execution)

**输入契约**：一个需要找回/备份/迁移的 Gandi 作品 + 明确目标（回退版本 / 取回角色 / 捡回误删 / 换机迁移 / 导出）；重大改动前建议先手动"保存到电脑"。
1. **先固化现状**：动手回退前"保存到电脑"导出 .sb3（浏览器版尤其）；编辑器白屏时先把内存作品存成版本"编辑器出错时的作品"再重建界面/下载文件/用版本重开。判停：在协作房间先下载本地副本，关闭协作会永久移除。
2. **回退版本（如需）**：开版本历史 → 点条目看逐角色 diff →"预览"跑一下 →"还原到此版本"（当前自动存成"还原前"）或"取回其中的角色"。完成标准：目标状态恢复且保留"还原前"可二次回退；判停：协作房间不能预览、还原整个房间且需"导入/回退整个作品"权限。
3. **捡回误删（如需）**：文件→回收站→定位条目→"还原"。完成标准：角色连脚本/私有变量原样回作品，造型/声音回原角色末尾；判停：场景本身回不来、积木不进站靠 Ctrl+Z、清空须按两次。
4. **备份迁移**："保存到电脑"得 .sb3 → 换机用该文件打开 → 需要旧版本时靠该文件所在浏览器的版本历史（注意版本不随文件走，必要时先在国内浏览器导出）。完成标准：换机能打开且场景/尺寸/代码文件齐全；判停：16:9 比例（2.0）不在 .sb3 里需手动设。
5. **代码文件/导出（如需）**：代码文件新建/上传/改名(F2)/移动/搜索(Ctrl+Shift+F)/比较（右键"选择以比较"）→ 顶栏"发布"导出网页/桌面/安卓。完成标准：文件随作品进 .sb3、导出目标可用；判停：>50MB 拒收、扩展文件"添加到作品"目前不可用、导出仅嵌入宿主时提供。
**输出契约**：找回/迁移后的可用作品 + 一份 .sb3 备份 + （如回退）"还原前"版本记录；明确区分"存在文件里的"与"只在本机浏览器里的"数据清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 想用命令行批量改文件或跑断言——用 `cli-authoring`；本卡是界面文件操作与保全。
- 想设计/切换多场景、处理角色跨场景归属——用 `scenes-assets`；本卡只在备份层面提醒 .sb3 兼容。
- 要写扩展/插件或做服务端部署——超出文档使用范围。

### 作者在文档中警告的失败模式
- 把版本历史/回收站当备份：两者都存在本机浏览器（IndexedDB），换浏览器、清网站数据即丢，不写进作品文件、不跟账号走；"不能代替保存作品"。
- 多场景 .sb3 经原版 Scratch 保存：不支持场景的编辑器只看得到入口场景，在那里保存再拿回来，其它场景连同独占造型/声音静默全丢，且那边不报错。
- 协作房间不能整份还原：CLI `history restore` 在协作里不可用；网页还原需"导入/回退整个作品"权限且还原的是整个房间，不能预览。
- 关闭协作=云端永久移除：进入协作会替换当前作品、关闭前必须先下载本地副本。
- 回收站清空按两次；删文件夹不删内容且移到上一级不确认（可 5 秒撤销），与删角色/造型/声音"先确认+进回收站"不同。

### 文档的盲点 / 局限
- "添加到作品"（把扩展文件当扩展装）目前不可用：编辑器用 data: 地址、运行时只收 http/https。
- 16:9 比例（Gandi 2.0）不在 .sb3 里，需手动设；导出"仅支持 Gandi 2"选项变灰不带入。
- 代码文件 Ctrl+Shift+F 文件中搜索 >1MB 跳过、≤1000 条，中文输入法下可能被吃；Monaco 停输入半秒自动写回、会话保留撤销/光标但清数据会丢。
- 扩展文件旧写法按路径读 `getGandiAssetContent('角色1/武器/data.json')`，首段是角色名（舞台写"舞台"）。

### 容易混淆的邻近方法论
- "版本历史"（自动快照、可预览/整份还原/取回角色）与"回收站"（误删对象原位捡回）是两个不同兜底层：一个按时间点、一个按删除对象。
- "还原前"版本是系统自动存的二次回退保险，不是用户手动版本；预览期间不存，别把它当新编辑。
- 代码文件里的 `extension.js`（扩展入口）与通过扩展库安装的扩展是两回事，前者只能一个且在舞台根下。
