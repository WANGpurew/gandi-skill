# 多场景架构与素材复用

## R — 原文 (Reading)

> "一个作品可以分成多个场景。每个场景是一个完整的小作品，有自己的舞台、角色、脚本、造型、声音和变量：菜单一个场景，第一关一个场景，Boss 战一个场景，不必再让每个角色自己判断本关该不该出现。"
>
> — Gandi 3.0 功能文档·角色场景素材·多场景 / slug: scenes（源：candidates/framework.md f24）

> "切换场景时可以同时带一份数据过去，由目标场景接收。切换到场景 [X]，参数 [键] = [值]：携带这些键值切换过去。点 ➕ 可以多带几组，最多 12 组。"
>
> — Gandi 3.0 功能文档·场景积木·切换与参数 / slug: scene-blocks（源：candidates/case.md c10、principle.md p10）

> "资源库不是一个新的存放处。素材本来就按内容（md5）存着，资源库做的是给它一个作品级的身份……条目是库里的一行……用法是某个角色身上的那个造型 / 声音对象。"
>
> — Gandi 3.0 功能文档·资源库 / slug: asset-library（源：candidates/framework.md f26）

## I — 方法论骨架 (Interpretation)

把"大作品结构乱、素材一改全乱"的问题，用场景拆分 + 引用/副本两条线解决：
① **场景=完整小作品**——每个场景有自己的舞台/角色/脚本/造型/声音/变量，关键是把"在画面上"与"在运行"看成两件独立的事；由此推出三档状态（未加载/休眠/运行中）；
② **角色归属三态**——角色可属单个场景、指定名单、或跨场景"全局单例"（常驻）；"模块"是只放代码、可定义全局积木的角色，跨场景需设为跨场景角色；
③ **场景通信**——"切换到场景[X]"带参切换（≤12 组键值，键留空跳过），会立即停本场景其它脚本；收尾/存分数放"当离开本场景"（切换前执行、最多 3 秒）；广播可排队给休眠场景（需先让它在后台运行），"在后台运行场景"一次 ≤16 个、按需装入/卸载，"显示场景"让原场景继续后台跑；
④ **素材引用 vs 副本**——资源库按 md5 去重，看"条目 vs 用法"和引用数角标；复制角色/拖给角色=共用同一份，复制造型/"改为独立副本"=独立；改共用图时选"仅修改此角色"（自动分副本）或"全部更新"；
⑤ **素材库需联网**——"从库中选择"=下载新份，"从资源库"=加引用。
核心洞察：先定"角色归哪个场景/是否常驻"，再定"场景间怎么切与传参"，最后定"素材是共用还是独立副本"——共用改一处影响全部，独立副本才互不影响。

## A1 — 书中的应用 (Past Application)

### 案例一：多场景带参切换（worked_example，slug: scene-blocks / c10）
- **问题**：从菜单切到关卡场景时，要把关卡号、难度等数据一起带过去，由目标场景接收。
- **方法执行**：用"切换到场景[X]，参数[键]=[值]"，点 ➕ 多带几组（最多 12 组、键留空跳过）→ 目标场景用"当场景开始（带 ➕）"添加参数椭圆并右键改名（如"关卡"），拖出直接当值用 → 用"场景参数[键]"取值，用"有场景参数[键]?"区分"没带"和"带的空串"；DSL 写 `gandiScene.switchToWithParams("main", {关卡: 1, 难度: 2})`。
- **结论**：文档所述效果——切换时把一份数据交给目标场景；"设置场景参数"可暂存、下次切换一起发送，"清空场景参数"丢弃暂存但已收到的不受影响。

### 案例二：素材复用与独立副本决策（worked_example/decision-framework，slug: asset-library / f26）
- **问题**：多个角色想用同一张图，但又怕改这张图会误改到别的角色。
- **方法执行**：资源面板看条目与引用数角标 → 要共用就复制角色或把素材拖给角色（按 md5 共用同一份）→ 要独立就复制造型或"改为独立副本" → 改共用图时按需要选"仅修改此角色"（自动分出副本）或"全部更新"。
- **结论**：文档所述效果——条目是库里一行、用法是角色身上的造型/声音对象；改共用图首次会询问，删文件型素材不确认但可撤销。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 要做"菜单→关卡→Boss 战→结算"这种多阶段游戏，不想让每个角色自己判断该不该出现。
2. 想让某个角色（如主角、记分器）跨所有场景常驻，其它只在特定场景出现。
3. 切场景时要带分数/关卡/难度过去，或用广播通知正在休眠的场景。
4. 多个角色共用素材，担心"改一张图影响全部"，想知道该共用还是分独立副本。

### 语言信号
- "多场景 / 分关卡 / 菜单单独一个场景"
- "角色跨场景常驻 / 全局单例 / 模块"
- "切场景传参 / 带分数过去 / 广播给别的场景 / 后台运行场景"
- "复用素材 / 共用图 / 改一张图全变了 / 独立副本 / 资源库"
- "scene switch / cross-scene actor / asset library / shared vs copy"

### 与相邻 skill 的区分
- 与 `blocks-authoring`（also_read）：本卡管"作品拆场景、角色归属、场景通信、素材复用"；blocks 卡管"单场景内脚本分页、自制/全局积木、变量作用域"。全局积木要跨场景生效，需先在本卡把模块设为跨场景角色——这是两卡衔接点。
- 与 `project-files`（also_read）：本卡管场景设计与素材决策；project-files 管 .sb3 文件与版本。"多场景 .sb3 拿到原版 Scratch 保存会丢其它场景"是交界提醒：本卡强调设计阶段别用旧编辑器，后者强调备份迁移后果。

## E — 可执行步骤 (Execution)

**输入契约**：一个要拆成多场景（或已经在多场景里复用素材）的 Gandi 作品 + 场景划分方案（哪些阶段、哪些角色常驻）；重大结构改动前建议先存一个版本。
1. **先存版本**：场景新建/删除/复制/导入/替换都无撤销，动手前在版本历史存一版。完成标准：有可回退的版本；判停：协作房间不可用版本历史回退场景结构。
2. **建场景并定归属**：作品名旁胶囊"新建场景" → 给每个角色设归属（单场景/名单/跨场景全局单例）→ 理解三档状态由"在画面上×在运行"推出。完成标准：菜单/关卡/Boss 各自独立、常驻角色跨场景存在。
3. **接通场景通信**：用"切换到场景[X]"带参（≤12 组）→ 收尾/存分数放"当离开本场景"（≤3 秒）→ 广播给休眠场景（先"在后台运行场景"）→ 需要并行开后台场景（≤16）→ 按需装入/卸载。完成标准：切换带参到位、离开收尾执行、广播被休眠场景收到；判停：切换会立即停本场景其它脚本，"重新开始本场景"不触发"当离开本场景"。
4. **定素材共用/独立**：资源面板看条目与引用数角标 → 共用用复制角色/拖给角色，独立用复制造型/"改为独立副本" → 改共用图时按意图选"仅修改此角色"或"全部更新"。完成标准：该共用的共享、该独立的互不影响；判停：素材库需联网，改共用图首次会询问。
5. **调试场景**：Shift+绿旗从当前场景开始；DSL 里场景写名字、存的是 id。完成标准：从任意场景可单独跑通。
**输出契约**：一份多场景作品（场景结构 + 角色归属表 + 切换/广播通信脚本）+ 素材共用/独立决策清单 + 改动前的可回退版本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 单场景内的积木组织（分页/自制/全局积木/作用域）——用 `blocks-authoring`。
- 场景文件的打开/保存/备份/回滚——用 `project-files`。
- 场景里卡顿时排查性能——用 `run-debug`；素材画得不对——用造型/声音创作能力。

### 作者在文档中警告的失败模式
- 场景增删改无撤销：新建/删除/复制/导入/替换改的是作品结构，不在积木撤销栈、也进不了回收站；第一次 Ctrl+Z 只提示不撤，再按会误撤更早的积木编辑——必须靠版本历史，协作房间不可用此回退。
- 旧编辑器保存多场景会丢其它场景：拿到不支持场景的编辑器（如原版 Scratch）保存，除入口场景外全部静默丢失且不报错。
- 删场景本身回不来：场景变量/入口标记/顺序都丢，但里面角色会逐个进回收站可捡回；删文件夹不删内容且不确认（可 5 秒撤销），与删角色/造型/声音不同。
- 改共用素材想当然：复制角色=共用同一份，直接改会"全部更新"；要只改一处必须选"仅修改此角色"（分副本）或先"改为独立副本"。

### 文档的盲点 / 局限
- "场景"扩展在多场景作品里不可卸载。
- 带参切换最多 12 组、后台运行场景最多 16 个、带参广播最多 16 个（按位置对应）——超出需拆分设计。
- 广播给休眠场景要排队，且接收方须在场/运行或"在后台运行场景"；素材库依赖联网，断网只剩本地资源。

### 容易混淆的邻近方法论
- "在画面上"与"在运行"独立：由此组合出未加载/休眠/运行中三态；"显示场景"让原场景继续后台跑，"切换到场景"会停掉原场景。
- "复制角色"（共用素材）与"复制造型 / 改为独立副本"（独立素材）是两条不同的复用路径，别混。
- "全局单例跨场景角色"与"模块"（只放代码、定义全局积木的角色）是两个概念，但都可能被设为跨场景；前者管数据与常驻，后者管逻辑复用。
