## I — 方法论骨架 (Interpretation)

把"脚本越写越乱、重复越来越多"的问题，用三层组织手段系统化解决：
① **分页**——角色脚本多时按主题切成积木页（战斗/道具/UI），右键角色新建子页、F2 改名、Delete 删、脚本首块右键"移动到积木页"，Ctrl+P 转文件；根页恒定不占行、不可删改；分页只是编辑器组织方式，存 .sb3 仍是普通作品；
② **自制积木消重复**——积木栏"制作新的积木"，可加输入框/布尔/文本/积木堆/堆参数，选普通/返回圆角/布尔六边形三形状；要 C 型就加积木堆，把"执行( )"放进"重复执行"/"如果"/前后包裹等不同位置，得到循环/条件/包裹/多分支；配颜色/分类/悬停说明，改定义后调用块跟着变形且值不丢；
③ **全局积木跨角色复用**——只有"模块"（只放代码的角色）能定义；在模块里做自制积木并开"全局积木"开关（全作品不重名），多场景再开"所有场景"；改一次定义全作品一步同步，有角色在用就删不掉；
④ **变量作用域建时就选对**——三档：全局（所有场景共用）/仅本场景（默认）/仅本角色；切到全局别的场景那份值会丢、切到仅本场景别处积木失效、切到仅本角色别的角色看不见；名字冲突时"确定"置灰；
⑤ **注释承载文档与例子**——右键"添加注释"，支持 Markdown 就地渲染，拖工作区积木进注释成 `gandi-dsl` 副本、拖回得真积木；存纯 Markdown 非 HTML 防注入。
核心洞察：分页管"看得清"、自制/全局积木管"不重复"、作用域管"数据对"，而作用域改动不可撤销是最需要先想清楚的一步。

## A1 — 书中的应用 (Past Application)

### 案例一：自制 C 形积木封装重复逻辑（worked_example，slug: custom-blocks / f09）
- **问题**：多段脚本里反复出现同一段"对一组积木做相同处理"的逻辑，想封装成一个积木，但普通自制积木没有"积木堆"入口，无法把调用者的积木放进来跑。
- **方法执行**：积木栏"制作新的积木" → 点"添加积木堆"，积木当场裂开变 C 形 → 在定义里把"执行( )"放进"重复执行"内部做成循环型（或放进"如果"做条件型、放前后做包裹型）→ 配颜色、分类、悬停说明。调用者把自己的积木拖进 C 形口里。
- **结论**：文档所述效果——定义里用"执行( )"把那段积木跑一遍，形成循环/条件/包裹/多分支 C 型；改定义后调用块跟着变形且值不丢，堆参数椭圆"身体按写它的地方算"。

### 案例二：全局积木一处定义全作品同步（worked_example，slug: global-blocks / f10）
- **问题**：原版自制积木只属于做它的角色，多个角色要用就得抄多份，之后"改一处得改十处"。
- **方法执行**：角色面板"新建模块"（只放代码的角色）→ 在模块里做自制积木 → 打开"全局积木"开关（全作品不重名，分类自动填模块名）→ 多场景作品再勾"所有场景"让模块跨场景 → 各角色直接调用 → 改一次定义。
- **结论**：文档所述效果——定义改了，散在各角色里已摆好的调用块跟着一起变；有角色正在用的全局积木删不掉；关掉开关退回模块本地积木。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 一个角色脚本太多、工作区挤成一片，想按主题拆开管理。
2. 多段脚本重复同一逻辑，想封装成带参数的自制积木（尤其是能包住别人积木的 C 形）。
3. 多个角色（甚至多个场景）要共用同一段逻辑，想一处改全作品同步。
4. 纠结变量该建全局/仅本场景/仅本角色，或要给积木写说明文档与可复用例子。

### 语言信号
- "脚本太多怎么分 / 积木页 / 分页"
- "做个带参数的自制积木 / C 形积木 / 返回值 / 布尔积木"
- "多个角色共用一个积木 / 全局积木 / 模块"
- "变量作用域怎么选 / 改成全局会怎样 / 能不能撤销"
- "给积木写注释 / Markdown / 把积木放进注释"
- "custom block / global block / variable scope / code pages / 脚本组织"

### 与相邻 skill 的区分
- 与 `scenes-assets`（also_read）：本卡管"单作品内脚本与变量怎么组织"；scenes 卡管"作品拆成多场景、角色跨场景常驻、跨场景角色本身也是模块"。全局积木想跨场景生效要先在 scenes 卡把模块设为跨场景角色，两者衔接。
- 与 `gandi-guide`（also_read，路由入口）：查找/批量替换已有积木（Ctrl+F/Ctrl+H）、代码框折叠、快捷添加属于整理查找，走 gandi-guide；本卡专管"新建/设计积木结构"。查找不到积木不要来本卡。

## E — 可执行步骤 (Execution)

**输入契约**：一个脚本较多或有重复逻辑的 Gandi 作品 + 明确的组织目标（分页 / 封装 / 跨角色复用 / 定作用域）；跨角色复用需先有"模块"角色。
1. **分页整理（如需要）**：右键角色→新建子页→F2 改名→脚本首块右键"移动到积木页"。完成标准：脚本按主题落到不同页，根页不占行；判停：Delete 删页会连脚本/注释/框，先确认。
2. **设计自制积木**：积木栏"制作新的积木"→加输入框/布尔/文本/积木堆/堆参数→选普通/返回圆角/布尔六边形→要 C 型加积木堆并把"执行( )"放到定义中的不同位置→配颜色/分类/悬停说明。完成标准：调用块外形与参数符合预期，改定义后值不丢；判停：返回值/布尔形状与积木堆互斥（变灰）。
3. **提升为全局（如需跨角色）**：新建模块→在其中做自制积木→开"全局积木"开关（全作品不重名）→多场景再开"所有场景"→各角色调用。完成标准：一角色改定义、其余调用块同步变化；判停：只有模块能定义，普通角色开关是灰的；有角色在用删不掉。
4. **定作用域（建变量时）**：按"谁需要看见/共用"三选一——全局/仅本场景(默认)/仅本角色。完成标准：各角色/场景对本变量的可见性与值符合预期；判停：需改时在"修改变量"对话框逐档看红色后果提示再确认，名字重复则"确定"置灰。
5. **写注释**：右键积木"添加注释"→Markdown 就地写说明→拖工作区积木进注释成副本（可选拖回）。完成标准：说明可读、例子可取用；判停：旧 ```blocks 围栏不再识别，须用 ```gandi-dsl。
**输出契约**：一份组织后的脚本（分页结构 + 自制/全局积木库 + 变量作用域表 + 注释文档），以及"哪些逻辑被复用、哪些作用域被刻意选定"的说明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 只是查找/批量替换已有积木的值或结构——用 `gandi-guide` 的 Ctrl+F / Ctrl+H；本卡不负责维护已有代码。
- 排查运行期卡顿、变量异常——用 `run-debug`；作用域选对≠运行时值对。
- 设计场景拆分、跨场景角色归属——用 `scenes-assets`；本卡的全局积木只解决"逻辑复用"。

### 作者在文档中警告的失败模式
- 改作用域不能撤销：`Ctrl+Z` 作用于积木、不作用于作用域；改完第一次按 Ctrl+Z 只提示不撤，再按才撤更早编辑——为防"作用域改不回来却误撤上一次编辑"。建变量时就要选对。
- 全局积木同名：导入或手改作品出现同名全局积木时只认排在最前的那个，改一个两处都变，易误判。
- 删参数后积木移出：删掉自制积木的参数后，插在格里的积木会移出成为独立脚本，撤销不回来。
- 原版增强积木原版打不开：旋转中心偏移、带参广播、瞬时执行等"补全积木"依赖作品级"原版增强"设置，导出到原版 Scratch 打不开（≠ 例外）；光照/粒子/物理未适配旋转中心偏移。

### 文档的盲点 / 局限
- 云变量不能新建：新建对话框没有这一档，"数据管理"面板盖着"开发中"遮罩点不动（只能列出导入的云变量）。
- "只改变播放速度不变调"等部分增强能力尚未做；可扩展参数积木存 .sb3 会拆成原版嵌套结构。
- 广播改名收发同步但"无删除入口"（无人用时自动消失）；删全局变量若被别处引用会被拦下。

### 容易混淆的邻近方法论
- "全局积木"（所有角色可调用的逻辑）与"全局变量"（所有场景共用的一份值）是两回事，前者靠模块定义、后者靠作用域三档。
- "仅本场景"（变量默认档）与 scenes-assets 的"角色归属仅某场景"含义不同：一个是变量可见范围，一个是角色归属。
- 注释里的积木是副本（```gandi-dsl 围栏），拖回工作区才变真积木；旧 ```blocks 围栏已不兼容。
