# 扩展插件与多人协作

## R — 原文 (Reading)

> "扩展给作品加一批新积木：画笔、音乐、物理、图层、摄像头……装上之后积木栏底下就多一类。"

> — Gandi 3.0 功能文档·扩展 / slug: extensions（行19263；源：candidates/framework.md f41）

> "几个人同时编辑同一个作品：积木、造型、声音、代码文件、场景、资源库，谁改了哪里，别人那边马上就变。每个人的指针、正在看哪个角色，其他人都看得到。"

> — Gandi 3.0 功能文档·多人协作 / slug: collaboration（行20059；源：candidates/framework.md f42）

> "变量、列表、广播：增删、改名实时；变量的值只在建变量时带过去，运行时的值不同步……角色：新建、删除、改名、排序、属性栏里改的属性、舞台上拖动的位置实时同步。作品运行时角色的移动不同步。主题、布局、快捷键、插件、回收站：不同步，这些是每个人自己的。"

> — Gandi 3.0 功能文档·多人协作·什么会同步 / slug: collaboration（行20096/20099；源：candidates/principle.md p17、framework.md f43）

## I — 方法论骨架 (Interpretation)

把两条独立线索分清——"给别人装能力"（扩展/插件）与"和别人一起编"（协作）：
① **扩展 vs 插件**——扩展给作品加积木、随作品保存；插件改编辑器、装在本机不写作品。别把两者混为一谈；
② **扩展三装法**——扩展库点安装 / 填网址（.js、集市 ID、页面）/ 作品自带按 id 装回；没装上的扩展积木变灰占位（数据不改），装上后自动换回；TurboWarp 作品迁移只有库里认得移植版 id 才换，换错整个作品打不开；
③ **插件四类内置 + 外部**——内置四个（选择特定积木/下拉可搜索/查找定义/积木输入框增强），外部填网址或本机 .js（{id,name,setup}），宿主插件由宿主管；Gandi 2.0 插件不兼容不能直接装；
④ **协作发起**——顶栏两人图标 → 填账号（测试 uid+名字或宿主账号）→ 填协作名 → "用当前作品开启协作" → 邀请页按权限组生成链接。默认三组：管理员（改全部+管成员，不改组）/ 编辑者（改全部）/ 旁观者（只读可评论）；≤16 组、≤10 人，只有创建者能改组；
⑤ **同步边界（核心心智）**——只同步显式编辑的编辑态（积木/注释/代码文件/场景/资源库/引擎/地图实时，变量结构增删改名），不同步运行态（变量值、角色运行时移动/克隆）与个人偏好（主题/布局/快捷键/插件/回收站）；故"跑完保存当初始位置"不灵；
⑥ **协作内行为**——撤销只撤自己；点头像可"跳到他那里"（不改我布局）或"跟随"（布局临时换他的并锁住）；C 钉图钉评论、@、Ctrl+M 带位置快讯；关闭协作=云端永久移除，先下载本地副本；
⑦ **断线分流**——4401/4403/4409/4410 需重新加载，4400/4408/网络断自动重连（0.5→15s 退避）。
核心洞察：扩展/插件改的是"工具箱"，协作只对"显式编辑"同步，撤销与断线都按"谁的改动、哪种异常"分流。

## A1 — 书中的应用 (Past Application)

### 案例一：开启协作并按权限组邀请（worked_example，slug: collaboration / c15）
- **问题**：几个人要同时编辑同一作品，并要控制谁能改什么。
- **方法执行**：点协作图标 → 测试账号登录（或宿主账号）→ 填协作名 → "用当前作品开启协作"（角色/造型/声音/代码文件/场景/资源库全带进去）→ 在"邀请"页给某权限组生成链接发给别人 → 用新建协作自带的三组（管理员/编辑者/旁观者）控权限，创建者可在"权限组"页改组名、勾权限、新建组（≤16）。
- **结论**：文档所述效果——进入后多人实时协作、能看到彼此指针与改动；权限实时生效，越权改动被服务端撤回。关闭协作会从云端永久移除，须先下载本地副本。

### 案例二：C 钉评论与 Ctrl+M 带位置快讯（worked_example，slug: collab-comments / c17、c18）
- **问题**：想针对某块积木或画布某点与协作者异步讨论，或在聊天里指着画面某处说"这里有问题"。
- **方法执行**：协作中按 C 光标变评论气泡 → 在积木/造型/装配/声音编辑器点一下钉图钉（钉在积木上图钉跟随积木移动）→ 写评论 Enter 发表、Shift+Enter 换行、Esc 取消 → 点图钉展开讨论串，✓ 标已解决、⋯"跳到位置"。另在画面按 Ctrl+M 出现跟随鼠标的输入框，Enter 发到聊天并记下此刻画面位置、Esc 取消。
- **结论**：文档所述效果——评论/图钉只在协作里有、不写进作品，讨论串标题显示具体位置（如"角色1 · 等待 0.1 秒"）；只有 Ctrl+M 发的快讯记位置，面板里直接发的不带位置。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 想给作品装扩展（画笔/音乐/物理等）或填网址装自定义扩展、迁移 TurboWarp 作品。
2. 想和几个人同时编辑一个作品，或控制谁只读、谁能改。
3. 协作中发现"变量值/角色位置没同步"、"撤销撤到了别人的改动"，想知道为什么。
4. 协作者掉线或自己被移出/越权，想知道是等自动重连还是要重新进入。

### 语言信号
- "怎么装扩展 / 装插件 / 填网址装 / TurboWarp 移植 / 积木变灰"
- "多人协作 / 同时编辑 / 邀请链接 / 权限组 / 谁能改"
- "为什么没同步 / 变量值不同步 / 位置没跟上 / 撤销只撤自己"
- "跟随别人 / 跳到他那里 / 钉评论 / @ / 快讯 / 关闭协作"
- "断线 / 重新加载 / 4401 / 重连 / install extension / collaboration / presence"
- **反例信号（不触发本卡）**："写扩展的 compile 函数 / 注册点 / SDK 接口 / 引擎 API" 属扩展开发者的 API 细节，不在本卡范围（只讲选用与安装，不写代码）。

### 与相邻 skill 的区分
- 与 `project-files`（also_read）：本卡管协作发起/权限/同步边界；project-files 管 .sb3 打开保存与版本回滚。关闭协作前先备份、协作房间不能整份还原——备份动作交 project-files，协作语义交本卡。
- 与 `cli-authoring`（also_read）：本卡管编辑器内协作；CLI 卡管命令行读写。"协作房间不能整份还原、不能在进入那一刻写入"是两卡交界。
- 与 `engine-tools`（also_read）：地图在协作里是只读、需"编辑角色"权限，引擎配置规则在 engine 卡，本卡只讲协作态约束。

## E — 可执行步骤 (Execution)

**输入契约**：一个要装扩展/插件或要开协作的 Gandi 作品 + 用途意图（装能力 / 多人编辑）+ 想邀请的成员与权限分配；协作前作品须已保存到本地。
1. **扩展选型与安装**：扩展库按分类筛选 → 点卡片看详情与真积木预览 → 选装法（点安装 / 填网址 .js·集市 ID·页面 / 作品自带按 id 装回）。完成标准：积木栏多出该类；判停：作品还在用则拒绝卸载；断网只剩内置；TurboWarp 换错 id 整个作品打不开。
2. **插件管理（如需）**：设置→插件 → 内置四按需开关，外部填网址或本机 .js → 宿主插件由宿主管。完成标准：编辑器行为按预期改变；判停：插件不写作品、Gandi 2.0 插件不能直接装。
3. **发起协作**：顶栏两人图标 → 登录 → 填协作名 → "用当前作品开启协作" → 邀请页按权限组（管理员/编辑者/旁观者）生成链接 → 对方进入。完成标准：多人看到彼此指针与改动；判停：进入会替换当前作品（进入前先存）、≤16 组≤10 人、权限实时生效越权被撤回。
4. **按需协作内操作**：点头像"跳到他那里"（不改布局）或"跟随"（布局临时换他的并锁住，Esc/停止还原）→ C 钉评论/@、Ctrl+M 带位置快讯。完成标准：定位/讨论到位；判停：撤销只撤自己、自制积木定义有软锁（一次一人改）。
5. **判断同步疑惑**：问"这是显式编辑吗"——编辑态预期实时同步、运行态与个人偏好预期不同步。完成标准：能解释任何"为什么没同步"。
6. **断线分流与收尾**：看协作图标状态（绿已同步/黄同步中/红离线）→ 普通断线继续改等自动合并 → 红条"重新加载"（被移出/越权/整体替换/4401/4403/4409/4410）重新进入 → 关闭协作前先下载本地副本。完成标准：异常按类型正确分流，作品已备份。
**输出契约**：装好的扩展/插件（扩展随作品、插件在本机）+ 一个按权限组邀请好的协作房间（含成员与权限分配）+ 一份同步边界与断线分流的处理说明 + 关闭前的本地副本。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 写扩展/插件代码本身（开发者 API 签名/注册点/编译管线只作背景）——本卡只讲选用与安装。
- 单人编辑技巧、作品文件打开保存——用 `project-files` 或对应创作卡。
- 协作服务端部署、环境变量、发布回滚、测试分层等运维——文档明确不进使用范围。

### 作者在文档中警告的失败模式
- 关闭协作前不备份：关闭协作=从云端永久移除作品及协作历史并让其他人断开，须先下载本地副本。
- 运行态与个人偏好不同步：变量值/角色运行位置/克隆不同步，主题/布局/快捷键/插件/回收站各自独立——"跑完保存当初始位置"不灵；撤销只撤自己。
- 移植版 id 换错：TurboWarp 作品只有库里认得移植版 id 才替换，换错整个作品打不开。
- 越权/被移出/整体替换：越权改动被服务端撤回（界面闪一下）需重新进入；社区扩展装前先问。

### 文档的盲点 / 局限
- 规模上限：≤16 权限组、≤10 人（含所有者）；只有创建者能改组（管理员也不能）。
- 断线码分流：4401（票据无效/被移出/关闭）、4403（越权已撤回/无文档时写）、4409（连接数满，每协作 50 条）、4410（文档整份换掉）须重新加载；4400/4408/网络断自动重连（0.5→15s 退避）。
- 作品服务四面板（成就/排行榜/数据库/云背包）无宿主则盖"开发中"点不动、数据写死；素材谁都能读（知协作 id+md5 即可下载）。
- CLI 在协作里不能整份还原、不能在进入那一刻写入；被跟随者不能反跟随。

### 容易混淆的邻近方法论
- 扩展（加积木、随作品保存）vs 插件（改编辑器、装本机不写作品）——两者作用对象与保存位置都不同。
- "跳到他那里"（只挪视口、不改布局）vs "跟随"（布局临时换成他的并锁住）——两个定位动作语义不同。
- 评论里的"图钉讨论串"与积木的"注释"是两回事：评论不进作品，注释进作品。
- 关闭协作（永久移除、先备份）vs 退出/掉线（可重连）——前者不可逆，后者大多自动恢复。
