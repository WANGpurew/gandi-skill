# 运行调试与排错（卡顿/断点/静态检查）

## R — 原文 (Reading)

> "作品卡顿、脚本没有按预想运行、想知道哪块积木最费时，都可以在「调试」面板里查。它把运行中的作品拆开来看：每一帧花了多少毫秒、哪条脚本在占时间、哪块积木被执行了多少次。"
>
> — Gandi 3.0 功能文档·运行与调试·调试工作台 / slug: debug-overview（源：candidates/framework.md f31）

> "在一块积木上设断点，作品运行到那里就会停住，然后可以查看调用栈和变量、一块一块往下走。用法与代码调试器一致，区别只在于这里的「一行」是一块积木。"
>
> — Gandi 3.0 功能文档·断点与单步 / slug: debug-breakpoints（源：candidates/framework.md f32）

> "帧间隔最大 0.1 秒。切到别的标签页时浏览器会把作品降到一秒一帧，切回来那一轮如果按 1 秒算，角色会一步跨过墙壁。超过上限就按 0.1 秒算，代价是：作品实际跑不到 10 帧时，游戏变成慢动作。"
>
> — Gandi 3.0 功能文档·帧间隔·上限 0.1 秒 / slug: delta-time（源：candidates/principle.md p05）

## I — 方法论骨架 (Interpretation)

把"作品不对劲"从盲目试错，落成一条由粗到细、层层收窄的诊断工具链：
① **先看实时状态**——F3 调试信息覆盖层看帧率/变量/探针，不挡操作，三页可切（F3+1..3）；
② **录制找卡顿**——调试工作台"录制/5秒"（轻档定位脚本、完整档定位积木且才有自耗时排行），把卡顿操作一遍后读概览结论卡（按严重度红橙蓝排、取最多 8 条），在帧页找慢帧、积木页看自耗时排行，点"跳到积木"直达问题代码；
③ **断点单步**——Shift 点/右键设断点，命中自动切解释模式，看调用栈与变量，F8 继续 / F9 单步(进过程) / F10 跳过 / Shift+F9 跳出，可加条件断点、每 N 次停、日志点、变量被改/广播/克隆时停；
④ **改值验证**——数据面板按作用域分组，条件搜索 `<0`/`=NaN`/空找异常值，临时改一个值看效果（与舞台监视器互不影响）；
⑤ **静态体检**——"问题"面板不运行、不录制就扫出未定义变量/缺扩展/没帽子脚本等结构毛病，按错误/警告/提示分级；诊断十三条规则按严重度取 8 条；
⑥ **帧率无关改造**——把"每帧走一点"的数值换成"每秒()"（原数×原帧率，如 30 帧移动 10 步=每秒 300 步），帧间隔上限 0.1 秒，画面要顺再叠加补帧；
⑦ **关键前提**——编译模式默认开、随作品保存、数量级提速，但设断点会临时关并切回解释模式。
核心洞察：F3→录制→概览/帧/积木→断点单步→数据面板→静态检查，先定位再修；编译与断点互斥。

## A1 — 书中的应用 (Past Application)

### 案例一：卡顿诊断全流程（scenario，slug: debug-overview / f31）
- **问题**：作品卡顿、脚本没按预想跑、想知道哪块积木最费时。
- **方法执行**：F3 看帧耗时/状态 → 开调试工作台点"录制"（或"5秒"）→ 点绿旗把卡顿操作一遍 → 停止 → 读概览结论卡（按严重度红橙蓝排序）→ 帧页找慢帧、积木页看排行 → 点"跳到积木"。重作品先用"轻"档定位脚本，再切"完整"档定位积木。
- **结论**：文档所述效果——层层收窄可从"卡"定位到具体积木；缓冲上限 3600 帧/30fps 约两分钟、20 万条，录太久只剩末尾；结论去重会让成立规则不显示，去线程/积木页看原始数字。

### 案例二：断点单步排错（worked_example，slug: debug-breakpoints / f32）
- **问题**：某条脚本运行到中途行为不对，想逐块看执行过程与变量变化。
- **方法执行**：Shift 点/右键在目标积木设断点 → 运行时命中（自动切解释模式）→ 看调用栈、直接改变量 → F8 继续 / F9 单步进过程 / F10 跳过 / Shift+F9 跳出 → 按需加条件 `{变量}>100`、每 N 次停、日志点。
- **结论**：文档所述效果——用法与代码调试器一致，只是"一行"换成"一块积木"；编译模式默认开，设断点须临时关（断点只在解释模式、不写作品）；暂停语义是停在目标块之前、该块尚未执行。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
1. 作品运行卡顿、掉帧，想知道哪条脚本、哪块积木最费时。
2. 脚本"跑起来没报错但就是不对"，或变量值异常（负值、NaN、空）。
3. 想像代码调试器那样打断点、单步、看调用栈，或只在某条件下停。
4. 想让移动速度与帧率无关、切标签页回来不一步跨墙，或画面不够顺要补帧。

### 语言信号
- "作品卡顿 / 掉帧 / 哪块积木最费时"
- "打个断点 / 单步 / F8 F9 F10 / 调用栈"
- "变量值不对 / NaN / 数据面板改值"
- "没报错但行为不对 / 结构检查 / 诊断 / 问题面板"
- "速度跟帧率无关 / 每秒() / 补帧 / 帧间隔 / debug / breakpoint / profiling / delta time"

### 与相邻 skill 的区分
- 与 `cli-authoring`（also_read）：本卡是人在调试面板里诊断"为什么卡/为什么不对"；cli 卡的 `run/view/state/assert` 是后台自动化验证"结果对不对"。要定位根因用本卡，要无人值守断言用 cli 卡。
- 与 `engine-tools`（also_read）：引擎卡管物理/光照/粒子/地图的搭建与上限；本卡管运行性能诊断。物理/光照装好却看不到效果（如环境光 100% 看不见灯）先看引擎卡；搭建后卡顿、积木执行慢看本卡。

## E — 可执行步骤 (Execution)

**输入契约**：一个能运行出问题的 Gandi 作品 + 可复现的操作序列（怎么触发卡顿/错误）；排查断点前允许临时关闭编译模式。
1. **定前提**：需设断点/单步时，先关编译模式（设断点也会自动切回解释模式）；不需断点则保持编译开以获准确性能数据。完成标准：调试面板处于所需模式。
2. **F3 看状态**：运行作品按 F3 看帧率、变量、探针；F3+1..3 切页，按 E/B/P/N/L/S 编辑/碰撞框/暂停/单帧/锁定/复制。判停：若只是读一个值不必录制，直接在 F3 页面拖积木求值。
3. **录制定位卡顿**：调试工作台点"录制/5秒" → 操作一遍 → 停止 → 读概览结论卡 → 帧页找慢帧、积木页看自耗时 → "跳到积木"。完成标准：定位到具体积木；判停：重作品先用轻档，缓冲 3600 帧/20 万条别录太久。
4. **断点单步（如需）**：Shift 点/右键设断点 → 命中后 F8/F9/F10/Shift+F9 → 加条件/日志点/每 N 次停 → 看调用栈与变量。完成标准：复现出问题那一步的变量/调用状态；判停：给已运行的编译脚本设断点须停止重跑才命中。
5. **改值与静态体检**：数据面板按作用域搜 `<0`/`=NaN`/空、临时改值看效果；打开"问题"面板做静态结构检查（未定义变量/缺扩展/没帽子脚本），逐条修复后"重新检查"。完成标准：异常值归位、静态检查无错误级条目。
6. **帧率无关（如需要）**：把"每帧走一点"的数值按"原数×原帧率"换成"每秒()"，画面要顺再叠加补帧。完成标准：切标签页回来不跨墙、低帧率下速度不失真；判停：帧间隔上限 0.1 秒（低于 10 帧会变慢动作），"不限"帧率下插值失效。
**输出契约**：一份诊断结论（结论卡/慢帧/自耗时排行/断点处变量快照）+ 已定位到的问题积木 + 修复记录（改值或改为"每秒()"）+ 可选 `.gtrace` 录制基线。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 编辑期找不到某块积木、想批量替换值——用 `gandi-guide` 的整理查找（Ctrl+F/Ctrl+H）或 `blocks-authoring`。
- 纯素材问题（造型画得不对、声音有噪声）——用造型/声音创作能力，调试工具查不了画面美感。
- 想做后台自动化断言而非人工诊断——用 `cli-authoring` 的 run/view/state/assert。

### 作者在文档中警告的失败模式
- 失控"不刷新屏幕"循环：勾了该选项又写 `while(true)`，线程每帧占满 500ms；连续两轮用满即判定失控、压到 40ms/帧——**只限速、不停止也不跳过**，死循环照常执行，别以为编辑器替你停了。
- 带编译模式排查报错：编译过的脚本报错方式不同、少数积木行为有细微出入，会被误导；排查或逐步观察要手动关编译模式。
- 不限帧率：设为"不限"跟屏幕刷新率跑，动画插值不起作用（每帧本来就是真的），别指望靠它补帧。
- 数据面板改值不可撤销：等同在舞台监视器上改值，标记未保存改动、协作按规则同步，但 `Ctrl+Z` 撤不回；且尚未提供对象/广播/表达式三页、改动记录、条件断点、快照比对、钉到舞台。
- 设断点后运行在编译脚本上不命中：须停止并重新运行；不设断点按 F8 停在第一条运行线程。

### 文档的盲点 / 局限
- 调试工作台缓冲上限 3600 帧（30fps 约两分钟）/20 万条记录，录太久只剩末尾；结论去重（同一积木只留最靠前一条、最多 8 条）会让成立规则不显示，须去线程/积木页看原始数字。
- 诊断十三条规则偏重"界面开销/无等待循环/广播风暴"等，判定经验化（如"无等待循环"=一帧同一段脚本跑 200 块以上），非精确根因。
- F3 覆盖层发布后不能按；终端关闭即解除接管、`console.log` 不进终端（须用 log/info/warn/error）。

### 容易混淆的邻近方法论
- "补帧/插值"（画面顺）与"帧间隔/每秒()"（速度独立于帧率）是两件事，可同时用；不限帧率时前者失效。
- "概览结论卡"（需运行+录制，诊断运行时性能）与"问题面板"（静态结构检查，不需运行）结论来源不同，别混为一谈。
- 数据面板的"改值看效果"与舞台监视器改值等价，都不是改积木脚本本身。
